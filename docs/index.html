Chrome extension · Manifest V3 · unofficial

The site you're on might already be discounted.

CB Deal Finder checks whatever page you're browsing against your employer's Corporate Benefits portal and puts a count on the toolbar icon when there's an offer. One click takes you to it.

It uses the login you already hold in your browser — it never asks for a password — and it downloads the offer catalogue once a week so that every match afterwards is decided on your own machine.

How it works

Set it up once, then forget about it

Every employer has its own portal address — something like yourcompany.mitarbeiterangebote.de. You enter yours once and approve access to that single domain. Nothing wider is requested.

  1. 01

    The catalogue arrives weekly

    The extension reads the portal's own category navigation, then fetches each category page — spaced 1.5 s apart, never as a burst — and stores brand names and offer links locally.

  2. 02

    Matching happens offline

    A site's brand is guessed from its domain, and optionally from the page title. Both sides are normalised — lowercased, umlauts folded, punctuation dropped — and compared locally. Zero requests.

  3. 03

    The badge counts

    Matches show as a number on the toolbar icon. Click it for the list, or search any brand by hand from the same popup regardless of where you are.

Portal load

Why the catalogue, and not a search per page

The obvious design — query the portal's search on every page you visit — does not scale. Measured on the earlier version of this code, that was around 2.4 requests per page view (misses cost the most, because the candidate loop only stops on a hit), and every tab switch triggered a full rescan with no caching at all.

Design Requests / user / day At 1,000 users
Search on every page view ~600 600,000
Weekly catalogue (what it does now) ~2 2,000

The property that matters is that the cost no longer scales with browsing: a heavy surfer costs the portal the same as someone who barely opens their browser. Failed syncs back off rather than retrying on every page, so an expired login can't turn into a steady drip of rejected requests either.

Controls

You decide how much it does

Everything beyond the plain badge is opt-in, and every setting can be turned back down.

Automatic finding — off by default

On, it registers a tiny content script that reads a page's <title> and og:site_name — nothing else — so the badge is right without opening the popup. That needs the broad all-sites permission, which is exactly why it's off until you ask for it.

How loudly a match is announced

Badge only, a desktop notification, or an attempt to open the popup (Chrome frequently blocks that outside a click, so it falls back to a notification). Restored tabs after a browser restart never announce themselves — you didn't just open those pages.

Switch sites off, by pattern

Silence a site from the popup — until the browser closes, or for good — or add a pattern in the settings: *.example.com covers every subdomain. The badge keeps counting there; only the alert stops.

What counts as a brand name

The domain always counts. The page title finds more — it's what catches easyairportparking.de — but on sites that aren't shops a stray title fragment can mislead, so titles only ever match a brand exactly, and you can switch them off entirely.

Privacy

Nothing leaves your browser

  • No account, no password. The extension reuses the session your browser already holds with the portal. It doesn't have the cookies permission and cannot read them.
  • One destination. Requests go only to the portal origin you entered and approved. Not to the developer, not to anyone else.
  • Two fields per page, at most. The tab's address, and — when enabled — its title and og:site_name. No page content, no form fields, no input.
  • No analytics, no remote code. Fonts are bundled with the extension rather than fetched. There is nothing to phone home with.
  • Local storage only. Your portal address, your settings and the cached catalogue live in chrome.storage. Removing the extension deletes all of it, because no copy exists anywhere else.

Install

Two minutes, once

Install from the Chrome Web Store, then point it at your portal.

  1. Add CB Deal Finder to Chrome, and pin it to the toolbar so you can see the badge.
  2. Click the extension icon, then the gear, and enter your portal address — the one you normally sign in at, e.g. yourcompany.mitarbeiterangebote.de. It's checked before it's saved, so a typo can't silently replace a working one.
  3. Approve Chrome's prompt. That grants access to that one portal domain and nothing else.
  4. Make sure you're signed in to the portal in a normal tab, then browse. The badge starts counting.
  5. Optional: in the same settings page, turn on automatic finding and choose how loudly a match is announced.

Prefer to run it from source? Every release is also published as a ZIP on GitHub, which you can load via chrome://extensions → Developer mode → Load unpacked.

Honest limits

What it doesn't do

Worth knowing before you install, rather than after.

Discount figures can be out of date

Brand names are stable; percentages and monthly specials are not. With a one-week cache lifetime a figure can lag, so the popup always shows the catalogue's age and offers a refresh. The authoritative number is on the portal page the link leads to.

Without automatic finding, the badge can under-count

On its own the badge uses the domain guess alone, which is right for most brands but misses ones whose domain doesn't split into words. Opening the popup always runs the more accurate title-based check.

Single-page apps may not trigger a rescan

Navigations that don't produce a full page load won't re-run the check until you switch tabs or reload. The popup's manual search covers that case.

Regional offers can't be filtered by location

Location-dependent offers are in the catalogue by brand, but the local matcher has no idea where you are. Use the search box for those.

One portal at a time

Saving a new portal address replaces the previous one. There's no multi-portal mode.

It depends on the portal's HTML

Offers are parsed out of the portal's own pages. If the portal restructures its markup, the parser needs updating — that's the nature of working against a site with no public API.
